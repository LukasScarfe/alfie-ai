# Screens: the contract between engine, card and screen modules

Milestone 3's interfaces, fixed before the code so agents can build the parts in parallel.
design.md "Screens" says what screens are; this says how the pieces fit together. Change it
only together with every side that uses it.

## Files

| Path | Owner | What |
|---|---|---|
| `frontend/screens/<type>.json` | each screen type | the type's metadata and option schema (below) |
| `frontend/screens/<type>.js` | each screen type | the type's drawing module (below) |
| `frontend/alfie-screens.js` | foundation | the registry, the font layout (`text`, `width`) and the view helpers ported from xy `views.py` |
| `frontend/alfie-font.json` | foundation | the vector font, generated by `tools/font_dump.py` from xy `font.py` |
| `frontend/alfie-intros.js` | foundation (stub), then intros | transitions |
| `screen_types.py` | foundation | loads every `screens/*.json` and validates screen options |
| `providers/__init__.py` | foundation | the provider registry and cache base |
| `providers/<kind>.py` | each data kind | one server-side data source |

The Python files are under `custom_components/alfie/`, and the frontend ones under
`custom_components/alfie/frontend/`.

## A screen type's JSON (`frontend/screens/<type>.json`)

```json
{"type": "plot", "title": "Plot", "needs": "history",
 "options": [
   {"key": "entities", "kind": "entities", "label": "Series", "required": true, "domain": ["sensor"]},
   {"key": "hours", "kind": "number", "label": "Span (hours)", "default": 72, "min": 1, "max": 2160},
   {"key": "unit", "kind": "text", "label": "Unit", "default": ""},
   {"key": "style", "kind": "choice", "label": "Line", "default": "solid", "choices": ["solid", "dotted"]},
   {"key": "markers", "kind": "bool", "label": "Markers", "default": true}
 ]}
```

- `needs` is `null` or one provider kind: `history`, `forecast`, `calendar` or `streets`.
- Option kinds are `entity`, `entities`, `number`, `text`, `choice`, `bool` and `color`.
- `domain` optionally limits entity options to some domains.
- Python (`screen_types.py`) validates a screen's `options` against this. It fills defaults,
  checks numbers and choices, and checks that entity options are entity ids. The panel renders a
  form from it.

## Config sections (in `config.py`, stored like the others)

```json
"screens":   [{"id": "plants", "type": "plot", "title": "Plants", "options": {...}}],
"rotations": [{"id": "living_room", "name": "Living room", "transition": "draw",
               "face_seconds": 0, "steps": [{"screen": "plants", "seconds": 20},
                                            {"alfie": true, "seconds": 15}]}]
```

- Ids follow the signal id rule: lower-case letters, digits and `_`, and unique.
- A step names an existing screen, or is an Alfie step (`alfie: true`, no screen). `seconds`
  runs from 3 to 3600.
- `face_seconds` is Alfie between every pair of screens: from 0 to 3600, default 0 (off).
- `transition` is an intro style name or `random`.
- A signal's `screen` must name an existing screen or be empty. That check comes in once screens
  exist; until then the field stays free text.
- Both sections default to `[]`, because Alfie ships no screens of his own.

## Engine to card

- **Scene** (`alfie/subscribe`) gains two fields:
  - `"screens_rev"`: a short hash of `screens` plus `rotations`. A card refetches when it
    changes.
  - `"screen"`: `null`, or `{"id": "plants", "until": <epoch s>, "seq": <int>}`. Set by the
    `alfie.show_screen` service; M4 stories will set it too.
- **`alfie/screens`** (open to every logged-in user, because the wall tablet is not an admin)
  returns `{"rev", "screens", "rotations", "types"}`, where `types` is every type's JSON.
- **`alfie/screen_data {screen: id}`** (open to every logged-in user) returns
  `{"data": <json> | null, "at": <epoch s>, "error": <str> | null}` from the screen's provider
  cache. Screens with `needs: null` never call it.
- **Service** `alfie.show_screen {screen, seconds = 20}`: every card presents that screen now,
  then resumes what it was doing.

## Providers (`providers/<kind>.py`)

```python
@register("history")
class HistoryProvider(Provider):
    ttl = 3600                      # seconds a cached answer stays fresh
    async def fetch(self, hass, screen: dict) -> dict: ...   # JSON-able, small
```

- The registry's base class caches per screen id plus a hash of its options, and gives one
  in-flight fetch per key.
- Blocking work goes to `hass.async_add_executor_job`.
- A provider never runs for a screen that doesn't exist, and fetches only when a card asks for
  data (lazy), then keeps it for `ttl`.
- Failures give `{"data": null, "error": "..."}` and an exponential backoff, capped at the
  `ttl`.
- Results are kept small: series bucketed to 60 points or fewer, simplified street geometry.
- Each provider file adds one import line to `providers/__init__.py`.

## A screen module (`frontend/screens/<type>.js`)

```js
export default {
  type: "plot",
  // Called once per frame while the screen is visible. It must be cheap: cache anything slow on
  // `memo`, which belongs to this screen instance and persists between calls.
  draw({ w, h, t, data, options, states, config, memo, S }) { return strokes; },
};
```

- **The box:** x runs over [-w, w] and y over [-h, h], with y up, in the face's units (the
  ring has radius 1). The card picks `w` and `h` from its aspect and the presenting style.
- `t` is epoch seconds, `data` is the provider's data or null, and `options` is validated with
  defaults filled in.
- `states` is `hass.states`, and `config` is `hass.config` (latitude, longitude, time_zone,
  unit_system).
- `S` is `alfie-screens.js`: `text`, `width`, the helpers and the icons.
- **A stroke** is `{pts: [[x, y], ...], closed: bool, w: number, role: "line" | "text" | "accent" | "dim", fill: bool}`.
  - `w` is a weight. 1 is normal, more than 1 is bolder, and 0.15 is xy's "dotted": the card
    draws it dashed and dim.
  - The card maps `role` to its colours (face colour, text colour, accent colour, dim) and
    strokes everything with its style's glow and the same smoothing as the face.
- With no data yet, a screen draws a placeholder, such as its title in the font, never nothing.

## Intros (`frontend/alfie-intros.js`)

```js
export const STYLES = ["cut", "fade", ...];
export function presence(style, u, leaving)      // u in [0, 1] -> presence 0..1 (may overshoot)
export function apply(style, p, leaving, strokes, box) // -> {strokes, alpha}
export const SECONDS = { cut: 0, fade: 0.6, ... };
```

The foundation ships `cut` and `fade`, and the intros agent adds the rest. The face uses the same
calls when it leaves and arrives in "hand over".

## Card

- **Options:**
  - `mode: companion | rotation`;
  - `rotation`: a rotation id, or an inline `[{screen, seconds}]`;
  - `present: handover | corner`;
  - `corner: bottom_right | bottom_left | top_right | top_left`;
  - `corner_size` (0.15 to 0.5, default 0.3);
  - `transition` (overrides the rotation's);
  - `appear_story`: `auto` (mood-led, default), `none`, or a story id;
  - colours `text_color` and `accent_color`.
- **Rotation runs in the card:** a timer, which pauses while hidden. A screen step shows its
  screen for `seconds`, then the next screen follows with Alfie kept away (or in his corner).
  An Alfie step (or a `face_seconds` gap) brings him on: the card asks `alfie/story/expand` for
  the most relevant story's timed actions and plays them itself, and the step lasts at least as
  long. The logic is pure, in `frontend/alfie-stage.js` (`advance`, `runStory`).
- A scene `screen` interrupts the rotation and the rotation resumes after `until`.
- **Hand over:** the face leaves by the transition, the screen enters, and at the end the reverse.
- **Corner:** the face shrinks into the corner (an animated scale and translate) and keeps
  living there. The screen box is the card minus a margin around that corner.

## Look and playground (M3 step E)

**Config section `look`** (in `config.py`, after `personality`; the defaults reproduce today's
card defaults exactly):

```json
"look": {"style": "neon", "face_color": "", "eye_color": "", "background": "",
         "text_color": "", "accent_color": "", "line_width": 0.035, "screen_line_width": 0.02,
         "glow": null, "eye_fill": false, "padding": 0.08,
         "shapes": {"head": {"type": "circle"}, "eye": {"type": "circle"}}}
```

- `style` is one of the card's styles (neon, flat, crt, theme).
- In the colour fields, `""` means "from the style". A value is a CSS colour, `#hex` or
  `var(--x)`.
- `glow`: null means "from the style", else 0 to 2.
- `shapes` holds the shape specs from design.md "Shapes are swappable data", checked for type
  and numeric ranges.
- The scene gains `"look": {...}` (the whole section; it's small).

**Card precedence:** a key set in the card's own config wins, then the scene's `look` (empty or
null values skipped), then the card's `DEFAULTS` and style.

**Card preview methods** for the panel (local only, never sent anywhere):
- `previewLook(look | null)`: use this look instead of the scene's;
- `previewExpression(name | null)`: hold an expression;
- `previewEnergy(value | null)`: hold an energy;
- `playLocal(name)`: already exists.

null ends a preview.
